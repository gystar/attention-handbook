# 7.5 信息覆盖与长上下文评估

稀疏方法减少了读取范围，也可能改变模型对信息的使用方式。评估应将选择质量、整模型能力与执行成本分开，再观察它们如何随稀疏预算变化。第三章讨论了通用的长上下文评估；本节补充连接和选择机制特有的比较条件。

## 选择覆盖与输出误差

对固定模型、固定输入，可以用 Dense Attention 的权重作为分析参照。令第 $$i$$ 行的完整权重为 $$p_{ij}$$，选中集合为 $$\mathcal A_i$$，定义保留质量：

$$
C_i=\sum_{j\in\mathcal A_i}p_{ij},\qquad \delta_i=1-C_i.
$$

$$C_i$$ 衡量保留了多少原始权重质量；7.1 的输出误差推导说明，还需考虑被删位置的 Value。另一个指标是对 Dense Top-r 位置的召回率：

$$
R_i=\frac{|\mathcal A_i\cap\mathcal T_i^{(r)}|}{r},
$$

其中 $$\mathcal T_i^{(r)}$$ 是完整分布中权重最大的 $$r$$ 个位置，要求该行至少有 $$r$$ 个有效位置。Quest 使用 Top-10 召回分析 Query 相关选择。[原论文 §3.3、Figure 4](https://arxiv.org/html/2406.10774v1#S3.SS3)

这些指标适用于同一表示上的剪枝诊断。若模型使用压缩 KV、独立分支或经过稀疏训练，内部权重未必与 Dense 模型逐位置对应，需要直接报告任务结果。生成轨迹变化后，还应区分使用同一固定前缀的比较与各模型自由生成的比较。

| 比较对象 | 需要固定或记录的条件 | 可以回答的问题 |

| 同一 Checkpoint 的推理期稀疏化 | 权重、输入、精度、选择预算 | 即时替换读取规则的影响 |

例如 NSA 的实验包含稀疏预训练，而 Quest 面向推理期页面选择；两者的成绩差异包含训练方式差异。NSA 的 LongBench 结果还使用了选定子集，论文明确排除了部分任务。[NSA §4.1—4.3](https://arxiv.org/html/2502.11089v1#S4) 引用均分时，应同时给出任务清单和聚合方式，避免将子集结果写成完整基准结果。

预算应分别记录原始位置数、压缩条目数、局部窗口、固定保留位置和 Indexer 元数据。多个 Query Heads 是否共享选择集合，也会影响实际 KV 读取量。将不同形态的条目都称为“读取 k 个 Token”，不足以说明计算和存储成本。

## 质量与延迟联合比较

至少同时报告任务得分、端到端延迟及峰值显存，并分别列出 Prefill 与 Decode。动态方案还需计入压缩、Indexer、Top-k、索引搬运与稀疏 Attention 的成本；保留完整历史 KV 的选择方法可能减少读取量，而缓存容量仍随历史增长。

对多个预算形成质量—延迟曲线，比单个稀疏率更便于查阅。若方法 A 在相同任务上得分不低于 B、延迟不高于 B，且至少一项严格更优，则在这两个指标下 A 支配 B；其余点体现不同取舍。硬件、实现和误差口径沿用[6.5 数值误差与性能评估](../flash-attention/evaluation.md)，训练预算和任务覆盖则按本节另行记录。
