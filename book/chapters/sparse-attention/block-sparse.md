# 7.3 Block-Sparse Attention 的组织与执行

稀疏连接只有被执行算法实际跳过，才会减少相应计算。Block-Sparse Attention 将位置配对组织为矩形块，调度被选中的块，在块内使用矩阵乘法。Sparse Transformer 已将固定连接模式组织为块级 kernel；FlashAttention 也可在分块计算时跳过不参与的块。[Child et al.，§5.5](https://arxiv.org/html/1904.10509v1#S5.SS5)；[Dao et al.，§3.3](https://arxiv.org/html/2205.14135v2#S3.SS3)

## 连接粒度与执行粒度

设一个分数块包含 $$b_q$$ 个 Query 和 $$b_k$$ 个 Key，总共 $$b_qb_k$$ 个配对。数学上的 Mask 可以只允许其中一部分位置，但执行单元可能仍需完成整个矩阵块的乘法，再将无效分数屏蔽。

| 层次 | 记录的对象 | 说明 |
| --- | --- | --- |
| 逻辑连接 | 实际允许访问的配对 | 决定 Attention 的数学输出 |
| 活跃块 | 至少包含一个有效配对的块 | 决定需要调度哪些矩阵块 |
| 块内 Mask | 活跃块中仍应屏蔽的位置 | 保持窗口边界与因果语义 |

以下为本书的计数示例：一个 $$8\times8$$ 分数矩阵仅允许对角线上的 8 个配对，块大小为 $$4\times4$$。若按整块执行，需要处理两个活跃块，共 32 个矩阵槽位，只有 8 个是有效连接；逻辑密度为 $$8/64$$，调度槽位密度为 $$32/64$$。块内 Mask 保证输出只使用对角线，但不会自动取消已经执行的其他乘加。

因此，评估需要同时记录有效连接比例和活跃块比例。块过大可能增加无效槽位；块过小则可能增加索引、调度和数据搬运成本。

## 在活跃块之间统一归一化

对于每个 Query 块，实现先取得活跃 Key 块索引，再逐块读取 Key、Value、计算分数和应用块内 Mask。各块的统计量按 [6.2 Online Softmax 与分块计算](../flash-attention/online-softmax.md) 合并，最终统一归一化。

若先对每块分别做 Softmax，再把输出相加，就改变了分母。Block-Sparse 改变的是参与集合，集合内仍应遵循同一行的 Attention 定义。重叠窗口或多个选择分支生成同一位置索引时，还需要去重；否则重复位置会在分母中被多次计数。独立归一化后再通过 Gate 组合的多分支结构，则具有另一种明确的运算定义，不能当作索引集合的简单并集。

## 调度成本需要单独计入

总执行时间可以按测量范围拆为索引构建、数据读取、Attention 计算及必要的结果合并。固定模式可以复用块索引；动态模式通常需要根据输入重新产生索引，且不同 Query 块的工作量可能不同。

固定块大小、活跃块数量与布局，也会影响 KV 在多个 Query 之间的复用。因此，两个逻辑连接数相同的模式，可能具有不同的运行时间。后续动态选择小节将进一步区分选择器的成本与选中块的计算成本。
