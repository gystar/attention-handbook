# 9.6 状态容量与检索能力

固定大小的状态使 Decode 的历史存储不再随序列长度增长，但模型仍需从中保留后续查询所需的信息。本节先分析单个状态的读取，再用关联检索任务说明如何评估完整模型。

## 加法状态中的信息干扰

考虑零初始状态、无衰减且不带归一化的加法更新：

$$
S_N=\sum_{j=1}^{N}k_jv_j^\top.
$$

用第 $$i$$ 个 Key 作为 Query，读取结果为：

$$
S_N^\top k_i=\|k_i\|_2^2v_i+\sum_{j\ne i}(k_j^\top k_i)v_j.
$$

第一项是目标 Value 乘以当前 Key 的范数平方，第二项是其他写入带来的干扰。单位范数且两两正交的 Key 可在这种读取方式下精确取回各个 Value；相关 Key 会让多个 Value 混合。Schlag 等人从 Fast Weight Memory 的角度分析了这一问题，并据此引入可修正已有关联的更新规则。[§4.1—4.2](https://proceedings.mlr.press/v139/schlag21a/schlag21a.pdf)

下面用两个单位 Key 展示干扰。设 $$k_1=(1,0)^\top$$、$$k_2=(\rho,\sqrt{1-\rho^2})^\top$$，对应标量 $$v_1=2,v_2=4$$。写入两组关联后，以 $$k_1$$ 读取得到 $$2+4\rho$$。

| 两个 Key 的内积 $$\rho$$ | 读取结果 | 相对目标 2 的偏差 |
| ---: | ---: | ---: |
| 0 | 2 | 0 |
| 0.25 | 3 | 1 |
| 0.5 | 4 | 2 |
| 1 | 6 | 4 |

## 状态维度与可区分的关联

$$d_k$$ 维空间至多包含 $$d_k$$ 个两两正交的非零 Key。这个性质说明上述无干扰构造的边界，但不足以把完整模型的最大上下文长度写成 $$d_k$$。

更一般地，在同一时刻固定状态 $$S\in\mathbb R^{d_k\times d_v}$$，对 $$m$$ 个 Query 按行堆叠为 $$Q_*$$，线性读取结果满足：

$$
O_*=Q_*S,\qquad \operatorname{rank}(O_*)\le d_k.
$$

若任务要求这一次读取同时给出 $$m$$ 个线性无关的 Value，且 $$d_v\ge m$$，就必须有 $$d_k\ge m$$。例如目标矩阵为 $$I_m$$ 时，其秩为 $$m$$。这里限定同一个状态、单次线性读取；多层非线性模型或不同时间的状态不属于这一推导范围。

有限精度还给出另一种直接约束：若历史只能通过一个包含 $$b$$ 比特的状态传递，该状态最多区分 $$2^b$$ 种情况。要对所有可能取值精确保存 $$m$$ 个独立、各有 $$A$$ 种取值的项目，并允许后续任意查询，就需要：

$$
2^b\ge A^m,\qquad b\ge m\log_2 A.
$$

这是本节按可区分状态数量给出的计数推导，适用于无其他历史通道的精确检索。任务允许误差、信息有冗余或只需保留部分关联时，需求会变化。比较模型时应统计所有层和 Head 的持久状态，并计入卷积缓存等其他历史信息。

## 用关联检索区分保留与更新

Associative Recall 要求根据查询 Key 找回先前出现的 Value。Multi-Query Associative Recall（MQAR）在一段序列中安排多个查询，用于观察模型能否同时保留多组关联。Zoology 给出了 MQAR 的任务定义，并结合合成任务和语言建模分析检索能力。[§3，Definition 3.1](https://proceedings.iclr.cc/paper_files/paper/2024/file/448fc91f669c15d10364ee01d512cc10-Paper-Conference.pdf)

一个简化例子是先提供 `A → 7, B → 2, C → 9`，随后分别查询 `B, A, C`，目标依次为 `2, 7, 9`。这些符号表示任务中的离散项目；在自然语言实验中还需说明实际 Tokenization。

| 测试变化 | 要区分的能力 | 应控制的条件 |
| --- | --- | --- |
| 增加不同 Key–Value 对数 | 同时保留更多关联 | 查询数量、状态大小、训练预算 |
| 增加写入与查询的间隔 | 跨较长历史保留信息 | 关联数、干扰内容、位置分布 |
| 重复 Key 并修改 Value | 根据任务规则更新关联 | 明确查询最新值、首次值还是历史版本 |
| 增加相似 Key 和无关内容 | 区分相关与无关写入 | Key 分布、重复率、干扰强度 |
| 在不同位置安排多个查询 | 持续写入时维持可用记忆 | 查询分布、是否继续写入及上下文长度 |

## 联合比较质量、状态与运行成本

评估应同时报告检索准确率随关联数和距离的变化、语言建模指标、实际状态字节数，以及训练、Prefill、Decode 的运行成本。固定参数量、固定训练 FLOPs 和固定推理内存是不同的比较条件，应分别说明。

Perplexity 是全体预测位置的汇总指标。若检索位置仅占一部分，总体接近仍可能伴随该部分的明显差异；可以按检索位置单独统计损失或准确率。Zoology 在 Pile 分项分析中，将上下文内重复出现、且在训练数据中出现不超过 1250 次的 bigram 的末位 Token 划为 AR Hits；这类位置占所分析 Token 的 6.4%。该启发式划分用于减少训练期记忆常见搭配的影响，模型比较结论限于论文所研究的架构、数据和训练设置。[§3](https://proceedings.iclr.cc/paper_files/paper/2024/file/448fc91f669c15d10364ee01d512cc10-Paper-Conference.pdf)

当固定状态难以同时满足压缩和精细检索需求时，可以让部分层保留显式 KV，其他层使用递推状态。第十章将围绕这种分工讨论混合架构及其成本。
