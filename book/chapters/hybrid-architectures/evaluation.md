# 10.7 模型能力与资源成本的比较

比较混合架构，需要同时明确比较对象和资源约束。两个发布模型的差异可能来自模块布局，也可能来自训练数据、蒸馏、MoE、参数规模或推理实现。架构结论应尽量依据控制这些因素的实验；部署选择则需要测量完整模型在目标负载下的表现。

## 先确定比较约束

| 比较约束 | 能回答的问题 | 仍需单独记录的差异 |
| --- | --- | --- |
| 相同参数量、数据和训练 Token 数 | 给定模型规模与数据预算下的质量 | 总训练 FLOPs、训练时间、状态大小 |
| 相同训练 FLOPs | 给定计算预算下的质量 | 参数量、训练 Token 数、实际硬件利用率 |
| 相同推理内存预算 | 同一设备容量下可服务的负载 | Batch、并发、延迟、精度与缓存策略 |
| 相同任务质量门槛 | 满足要求时的最低资源成本 | 不同任务的退化、失败率、运行条件 |

MoE 模型还要分别记录总参数和每 Token 激活参数。前者影响权重存储，后者参与计算量分析；Expert 路由分布与并行方式也影响实际运行。不能用一个“参数量”同时代表这些成本。

Jamba 的一个可参考做法是先在不使用 MoE 的条件下比较纯 Attention、Mamba 与两种 Attention:Mamba 比例。论文 Table 4 使用约 1.3B 参数、250B 训练 Token，随后再单独分析 MoE。这里的“纯 Mamba”仍采用 Mamba 与 MLP 交替的结构。[§6.1、Table 4](https://arxiv.org/html/2403.19887v2#S6.SS1) 这类消融有助于区分模块组合与 Expert 配置的贡献；它给出的比例选择仍受模型规模和训练设置约束。

## 将平均质量与精确检索分开

语言建模损失、常规任务与上下文精确检索反映不同能力。Perplexity 比较还应使用相同 Tokenizer、语料和计算方式；Tokenization 不同的模型，可采用统一单位的指标，但需给出具体定义。

检索评估至少应区分以下两类实验：

- **针对任务训练**：检验架构在指定数据与优化预算下能否学会该操作。
- **评估预训练模型**：检验给定训练过程是否已经获得该能力；Prompt、示例数量、输出格式及评分方式也是实验条件。

Griffin 论文分别进行了合成任务训练与预训练模型的 Phonebook Lookup 测试。Phonebook Lookup 使用在 MassiveText 上训练了 300B Token 的 7B Griffin，Prompt 包含两个任务示例；当上下文超过 1024 的局部窗口、窗口无法覆盖整份电话簿时，检索表现开始退化。这说明针对合成任务学会某种操作，与预训练后直接完成精确检索，是两类证据。[§6.2、Figure 6](https://arxiv.org/html/2402.19427v1#S6.SS2)

对混合模型，可固定有效关联数，改变查询距离；也可固定距离，增加关联数或相似 Key。窗口内外的分项结果有助于定位依赖直接 KV 读取的程度。长文本汇总、跨段推理和精确字符串检索应分别报告，避免用单一任务代替整体上下文能力。

## 分别测量 Prefill、Decode 与服务成本

Prefill 处理整段输入，适合比较分块并行与 Attention Kernel；Decode 逐步推进，受到参数读取、KV 访问和递推更新的共同影响。混合模型的缓存节省还可能提高可用并发，因此应区分固定 Batch 的单步性能与内存约束下的服务吞吐。

| 测量阶段 | 主要结果 | 必须固定或报告的条件 |
| --- | --- | --- |
| 训练 | Token/s、峰值内存、达到目标损失的时间 | 序列长度、有效 Batch、精度、Checkpointing、硬件及并行方式 |
| Prefill | 输入 Token/s、TTFT | 输入长度分布、并发、Chunk 大小、前缀缓存命中情况 |
| Decode | ITL、输出 Token/s、延迟分位数 | 已有上下文、输出长度、Batch、调度及缓存精度 |
| 持久状态 | 有效载荷与实际分配字节数 | 各层形状、窗口、递推与辅助状态、共享和碎片 |

TTFT 在服务场景中包含排队等开销，应与独立 Prefill Kernel 时间区分。状态只报告 KV 会漏掉递推和卷积缓存，只报告理论有效载荷又会漏掉分配开销。具体请求边界和内存计数沿用 10.5。

实现版本也是比较条件：Attention 是否使用适当的 FlashAttention 或稀疏 Kernel，递推层是否使用 Selective Scan、SSD 或分块实现，都可能改变结果。固定一种尚未优化的实现，只能支持该实现下的测量结论。

## 用消融定位收益与代价

先确定基线，再逐项改变 Attention 层比例、位置、窗口、递推状态维度或 Gate。层比例与宽度同时变化时，应记录参数和 FLOPs 的变化；若为了匹配参数量调整了 FFN，也要将其列为实验差异。

一个可执行的比较顺序是：

1. 在相同数据和训练预算下比较基线与混合配置，保留随机种子及重复运行结果。
2. 将质量拆为常规任务、窗口内检索、窗口外检索和长度外推，检查退化发生在哪里。
3. 对通过目标质量门槛的配置，分别测量 Prefill、Decode 和总状态，再在目标并发下测量端到端表现。
4. 对关键差异补做单因素消融，报告未控制因素与测量不确定性。

最终比较表应同时列出配置、质量和资源成本。若一种配置在全部目标指标上都不差，并在至少一项更好，它在这些指标下支配另一种配置；候选集合中未被任何其他配置支配的配置构成 Pareto Frontier，需要按任务取舍。10.3 中 H1 与 H2 的指标排序不同，就是应保留分项结果的例子。
